Controller Action Reference
===========================

Purpose
-------

This file is an offline design and annotation reference. Do not load it into every Controller inference call. The runtime prompt should remain concise and contain only stable decision rules.

Action set
----------

1. PROCEED
   Current execution is supported and needs no correction.

2. VERIFY_TARGET_SET
   Strategy and API behavior are known, but task-state completeness is not established.

3. LOOKUP_API_SPEC
   Correct recovery depends on API semantics not visible in the trajectory.

4. FIX_EXECUTION
   Strategy is correct and the exact local implementation/API correction is visible.

5. REPLAN
   Objective, evidence source, task interpretation, computation rule, destination, or overall strategy is wrong.

Primary decision tests
----------------------

REPLAN test:
Would the plan still fail if every API call and line of code executed perfectly?

- Yes: REPLAN.
- No: continue.

FIX_EXECUTION test:
Can the Controller state the exact corrected argument, token, field, computation, control flow, or call order using visible evidence?

- Yes: FIX_EXECUTION.
- No: continue.

LOOKUP_API_SPEC test:
Must API documentation be inspected before the correct execution can be determined?

- Yes: LOOKUP_API_SPEC.
- No: continue.

VERIFY_TARGET_SET test:
Are the plan and API behavior established, with only coverage, membership, preservation, mapping, outputs, or final state unresolved?

- Yes: VERIFY_TARGET_SET.

Important boundaries
--------------------

Known API correction vs unknown API semantics:

- Error explicitly names the valid parameter: FIX_EXECUTION.
- API default limit or pagination behavior is unknown: LOOKUP_API_SPEC.

Unknown API semantics vs incomplete coverage:

- Pagination method is unknown: LOOKUP_API_SPEC.
- Pagination method is known but pages remain: VERIFY_TARGET_SET.

Local failure vs strategy failure:

- Gmail is the correct evidence source, but the token was omitted: FIX_EXECUTION.
- Agent ignores Gmail and uses unrelated Venmo data: REPLAN.

Risk handling:

Risk is not an action category. Every non-PROCEED action already prevents execution.

- Unsupported targets: VERIFY_TARGET_SET.
- Unknown destructive/write semantics: LOOKUP_API_SPEC.
- Malformed write call: FIX_EXECUTION.
- Wrong target or strategy: REPLAN.

Trigger independence
--------------------

Trigger describes when the Controller is invoked, not the error category.

The same error may occur under different triggers:

- before_finish: Agent attempts failure completion after omitting an access token.
- no_progress: Agent repeats the same unauthorized call.
- before_write: Agent prepares a write using the wrong token.

All three may require FIX_EXECUTION.

Recommended evaluation
----------------------

Do not evaluate action quality from class balance alone.

Use a manually labeled boundary set and inspect:

- PROCEED false-block rate;
- REPLAN vs FIX_EXECUTION confusion;
- FIX_EXECUTION vs LOOKUP_API_SPEC confusion;
- LOOKUP_API_SPEC vs VERIFY_TARGET_SET confusion;
- whether the instruction actually enables recovery;
- whether later Controller decisions adapt after earlier advice is followed.

The runtime prompt should contain only a few high-value contrastive examples. Keep broader examples and annotation notes in this offline file.
